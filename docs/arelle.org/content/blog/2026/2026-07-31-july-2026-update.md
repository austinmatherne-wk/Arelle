In July, the Arelle team released versions **2.42.0** through **2.43.1**, with improvements to validation, conformance testing, and code quality.

## Validation and conformance

- **Multi-target filings**: ESEF validation is now filtered by filing target, and conformance testcases load all targets by default.
- **XBRL datatype handling**: Enumeration facets are matched in the value space rather than lexically, and timezone information is preserved for Gregorian date types.
- **Jurisdiction validation**: Dutch KVK duplicate-label checks now include concepts from base taxonomies.
- **Conformance testing**: Added configuration for the XBRL XSD test suite and improved the way formula parameters reach instance validation.
- **Code quality**: Continued expanding type-hint coverage across the desktop interface and validation code.

## A new home for Arelle

Arelle.org has a new design and now runs on GitHub Pages. The move gives the project a simpler, static home that can be maintained alongside Arelle itself.

The redesigned homepage explains what Arelle does and offers a direct way to explore a real filing in the iXBRL Viewer. Navigation now puts downloads, project updates, documentation, and the source repository within easy reach.

The Download page brings the current desktop, Python, and Docker installation options together. The site also presents supported XBRL specifications and jurisdiction rules separately from Arelle's XBRL International certification, making the scope of each clearer.

Visitors can choose a light or dark color scheme, and that choice carries into the Viewer. A refreshed About page and Project updates archive make it easier to learn about the project and follow its work. Arelle's technical documentation remains on [Read the Docs](https://arelle.readthedocs.io/) and is linked directly from the site.
